Run and submit

Start by running the supplied model. Then change the model or training code, keep the dataset and evaluator fixed, and submit all three runs for review. This page gives the commands for the reference model.

Install · Train · Check rare families · Validate · Submit

1. Install and download the data

Use Python 3.11 and a CUDA-capable PyTorch installation. A ranked run has one NVIDIA L40S, at most four CPU cores, and 16 GiB of host RAM. You can develop on other hardware; its timings will not rank against the L40S runs.

git clone https://github.com/mcox3406/mol-speedrun.git
cd mol-speedrun
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python fetch_data.py

The download is about 11 MB. The downloader verifies checksums and places the files in data/qcdge-v0/. You do not need the large source archive or new quantum-chemistry calculations.

Check that the code runs without a GPU
python race.py --device cpu --smoke --output runs/smoke.json

This uses a small sample to check the pipeline. It is not a valid competition run.

2. Run all three seeds

Choose your code, settings, and stopping rule before running the three seeds. Run them one at a time, in separate processes. A seed controls the random initialization and training order; requiring three reduces dependence on a single lucky run.

python race.py --seed 20260929 --output runs/reference-20260929.json
python race.py --seed 20260930 --output runs/reference-20260930.json
python race.py --seed 20260931 --output runs/reference-20260931.json

The reference stops when it meets every accuracy limit or reaches the time budget. Each run writes a report (.json), validation predictions (.predictions.csv), and model weights (.pt). Keep failed attempts too.

What you can change: the model, structure-derived features, optimizer, training loop, and evaluation schedule. Start from scratch using training data only. No external molecules, pretrained weights, or fitting to validation/audit labels. Read the complete rules before a ranked attempt.

3. Check the fixed model on rare families

After fixing all three validation runs, evaluate the checkpoint from seed 20260929 once on the separate rare-family set. Do not use this result to choose settings or retrain the submitted method.

python audit.py \
  --run runs/reference-20260929.json \
  --output runs/audit.json

This loader is for the reference architecture. If you use a different model, provide its checkpoint loader and produce the same prediction format and checkpoint/report hashes. The audit is reported separately, outside the training timer.

4. Recompute the scores

The independent checker reads your saved predictions and verifies the data, seeds, reported errors, and file hashes. It checks the numbers; maintainers still need to review and reproduce the timing.

python validate_submission.py \
  --runs runs/reference-20260929.json runs/reference-20260930.json runs/reference-20260931.json \
  --audit runs/audit.json \
  --output runs/submission.json

A passing result is labeled checks_passed_pending_reproduction. It does not automatically add a leaderboard entry.

5. Open a pull request

Submit to mcox3406/mol-speedrun with:

  • Your code revision, exact commands, software versions, and hardware allocation.
  • All three run reports and logs, including any failed attempts with the fixed method.
  • Validation and audit predictions, model checkpoints, and their SHA256 hashes.
  • A short account of the experiments used to choose your settings, and any earlier use of audit results.

Put small reports in records/<name>/. Attach compressed predictions and checkpoints as release assets or another persistent download; keep large files out of Git. Maintainers inspect the code and rerun the comparison before accepting a record.
